# AI가 코딩을 하고 사람이 직접 프로그래밍 언어를 다룰 필요가 없을 때 우리가 해야 할 것들에 대해

- 코딩이 사라진다는 말은 사람이 직접 파이썬 문법을 다루고 디버깅을 할 일이 없어진다는 말이지만, 인간이 아무런 기반 지식 없이 명령만 해도 된다는 말은 아니다. 우리는 설계를 하고 그 구조와 원리를 이해해야 한다

1. 시스템의 구조와 흐름
- AI에게 "로그인 기능을 만들어줘"라고 할 때, 내부적으로 어떤 일이 일어나는지 그 지도를 머릿속에 그려야 한다
    - 데이터의 흐름: 사용자 입력 -> 프론트엔드 -> API 호출 -> 백엔드 로직 -> 데이터베이스 저장으로 이어지는 과정을 이해해야 함
    - 컴포넌트 간의 관계: 각 기능이 독립적인지, 아니면 서로 긴밀하게 연결되어 있는지 알아야 AI에게 "이 부분만 수정해줘"라고 정확히 지시할 수 있음

2. 논리적 사고와 제약 조건
- 코딩 문법은 몰라도 '컴퓨터처럼 생각하는 법'은 필수적임
    - 예외 처리: "정상적일때는 잘 작동하겠지만, 사용자가 숫자를 넣어야 할 곳에 문자를 넣으면 어떻게 되지?"같은 질문을 스스로 던질 줄 알아야 함
    - 성능과 한계: 데이터가 10건일 때와 100만건 일 때 시스템이 어떻게 다르게 반응할지, 현재 기술로 가능한 영역인지를 판단할 수 있어야 함
    - 추상화: 복잡한 비즈니스 문제를 AI가 이해할 수 있는 작은 단계별 로직으로 쪼개서 설명할 수 있어야 함

3. 데이터의 구조
- 소프트웨어의 본질은 결국 '데이터를 어떻게 다루느냐'임. 코드는 AI가 짜주지만, 어떤 데이터를 저장하고 불러올지는 인간의 결정 영역
    - 데이터 모델링: "우리 서비스에는 사용자 이름, 이메일, 가입일이 필요해"라는 식의 데이터 구조를 설계할 줄 알아야 함
    - 관계의 이해: 사용자와 그 사용자가 쓴 게시물이 1:N 관계라는 정도의 개념만 있어도 AI를 다루는 수준이 천차만별이 됨

- 즉, 코더(Coder)가 아닌 디렉터(Director)
    - 언어: 코드의 대락적인 독해 능력(읽고 흐름 파악) 
    - 인프라: 클라우드, 서버, DB의 기본 역할 이해
    - 문제 해결: 문제를 작은 단위로 쪼개는 논리적 기획
